# Phase G — Signal confidence and conviction sizing

## 1. Phase summary

Phase G makes strategy conviction real without changing any trading gate.
Every strategy now emits a deterministic `confidence` score in [0.0, 1.0]
computed from the same feature margins its entry conditions used, with each
margin stored in `signal.confidence_components` for audit. `PositionSizer`
scales the risk budget DOWN from the `risk_per_trade_percent` ceiling via
`multiplier = lerp(min_multiplier, max_multiplier, confidence)` taken from
the new `position_sizing.confidence` config section; it can never exceed the
ceiling (asserted in code). Conviction flows into the structured sizing log
line, the decision trace, the TradePlan (domain + SQLite columns), the
dashboard Strategy card, and a new read-only AI tool. No entry is gated on
confidence in this phase; a floor may be added later.

## 10. Known limitations

1. `trend_margin` uses module constant `_EMA_DISTANCE_ATR_MIN = 0.25`
   mirroring `regime.trending.ema_distance_atr_min`; strategies cannot see
   `RegimeConfig`, so a yaml change to that threshold would silently
   desync the margin reference. Fixing needs a StrategyContext field —
   deferred.
2. Confidence weights are equal by construction; there is no per-margin
   weight config (spec asked only for `position_sizing.confidence` keys).
3. No minimum-confidence entry floor exists — conviction only shrinks
   size; a floor is explicitly a later phase.
4. Existing-DB migration: `TradePlanRow` new columns are NULL on old DBs
   (values remain in the JSON `payload`); fresh DBs get columns via
   `create_all`. No migration script — same convention as prior phases.
5. `engine.payload()["strategy"]["last_signal"]` serialises confidence
   automatically via `model_dump`; confirmed in code (`state.py:119`),
   not via a live API call in this phase.
