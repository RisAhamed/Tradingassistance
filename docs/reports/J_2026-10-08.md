# Phase J — Bounded live acceptance harness

## 1. Phase summary

Phase J adds a bounded live acceptance harness (`app/acceptance/`) that
proves a real Alpaca PAPER order can be submitted through the production
OMS funnel, observed, flattened, and reconciled — with the repository yaml
never modified, execution opened in-process only, and every exit path
restoring the gates. Four real direct-mode runs against Alpaca paper all
submitted successfully; all four hit slow paper-engine fills (>30s poll
window with zero poll errors), took the specified ambiguous path, and each
ended flat with reconciliation OK via the single `engine.flatten()` path.
No order was ever retried, no live endpoint was touched, no config was
changed.

## 4. Code changes

`app/acceptance/preflight.py` (new): `run_preflight(config, env, engine)`
runs the 11 checks (paper mode, env paper flag, non-live endpoint,
credentials, repository gates closed, AlpacaPaperBroker paper flag,
broker reachable + equity, broker flat for symbol, local flat, local OMS
empty), each returning `{name, ok, detail, timestamp}`. Constructs the
broker but only connects/disconnects — zero orders by construction.

`app/acceptance/direct.py` (new): `run_direct` — repository-state probe
engine for local checks → preflight (+ alpaca/alpaca config assertion) →
clamp quantity → in-process enable → rebuild runtime → connect broker →
`_await_snapshot` (connect provider, wait ≤60s for a priced snapshot
through the normal handler seam; mock providers are duck-typed pumped) →
single `OrderIntent` via `engine.oms.create` + `engine._submit` (same
funnel: execution gate, paper_cap, OMS) → `_poll_terminal` (bounded poll
with per-poll forensic logging, errors recorded not swallowed) →
FILLED path (position match record, flatten via `engine.flatten`,
30s zero-verification, reconcile) / REJECTED path (no retry, no flatten,
reconcile, exit 3) / AMBIGUOUS path (reconcile, no resubmit, flatten any
late exposure, exit 4) → `finally`: gates False, engine stopped, broker
disconnected. Exit codes 0/2/3/4/5/6.

`app/acceptance/pipeline.py` (new): same preflight/enable/cleanup;
subscribes to `ORDER_SUBMITTED`, `runtime.startup()` with alpaca/alpaca,
waits `pipeline_timeout_seconds` (exit 7 + `no_signal_within_timeout` on
timeout), then the identical close chain; halts the experiment after close.

`app/acceptance/reporting.py` (new): full JSON schema, `write_report`,
top/bottom safety banners, human summary.

`app/acceptance/__main__.py` (new): CLI incl. `--dry-run` (preflight +
plan only, exit 2 if any check fails).

## 9. Safety confirmations

- repository config.yaml untouched — sha256 identical before/after all runs.
- repository execution.enabled stayed false — asserted by preflight in every run.
- in-process execution bounded to a single order — order-intent built once per run; no loops.
- no retry on rejection or ambiguity — submit-call counts asserted == 1 in tests; real runs show one broker_order_id each.
- flatten used the engine's single flatten path — `engine.flatten(force=True, session_closeout=False)` in all close paths, including the D.4 untracked-position closer (in-kind dust 0.000997498 closed cleanly in run 1 cleanup).
- risk engine and paper_safety caps active during submission — proven: the first harness draft hit `paper_cap:invalid_price` without a market snapshot, which forced the `_await_snapshot` design (real evidence the caps bite).
- no new dependency — stdlib + existing stack only.
- RiskEngine / OMS / FillLedger / strategies untouched — no diffs under `app/risk/`, `app/orders/`, `app/accounting/`, `app/strategies/`.

## 10. Autonomous-trading readiness

- Can a real paper order be submitted end-to-end? **yes** — 4 real `broker_order_id`s, all accepted by Alpaca paper.
- Was the position read back correctly? **yes** — broker positions observed (incl. in-kind fee dust 0.000997498 vs 0.001 filled) and matched to fills at flatten.
- Was the position flattened and verified zero? **yes** — 4/4 runs ended `final_broker_zero true`, `reconciliation ok`, direct `get_positions() == []` after each.

Statement: the submit→fill→read→flatten→reconcile loop is proven on real
paper, BUT every observed fill arrived slower than the specified 30s poll
window, so no run exited 0. **Not yet ready to leave the engine running
autonomously with execution.enabled=true**: first either (a) extend the
poll window with evidence, or (b) accept exit-4-with-flatten as the steady
state, plus run pipeline mode once to prove the strategy-driven path.

## 11. Known limitations

- pipeline mode requires a live signal (may take hours); unit-tested via exit 7 only.
- direct mode does not exercise strategy logic, only broker plumbing (by design).
- no auto-scheduler; the human decides when to enable autonomous running.
- Alpaca paper filled all four 0.001 BTC IOC market orders slower than 30s (zero poll errors) — environment behavior, not harness failure.
- In-kind fee dust (0.001 → 0.000997498 held) handled by the existing broker-side alignment path.
