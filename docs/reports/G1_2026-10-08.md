# G.1 BUG FIX REPORT — config-sourced trend threshold + reproducible backtests

## 1. Phase summary

G.1 fixes two bugs without changing trading behaviour: (a) `breakout_momentum`
trend conviction now reads `ema_distance_atr_min` from `config.regime.trending`
through a required `StrategyContext` field instead of a hardcoded module
constant, so a yaml change can no longer silently desync the margin; (b)
synthetic backtests accept a fixed `backtesting.reference_start` anchor (plus
`--reference-start` CLI override) so the same seed + anchor + length yields
byte-identical candles, while `null` preserves the legacy utcnow-anchored path.

suite would go red, violating the higher-order "every existing test must
still pass" rail). The change is strictly limited to adding the constructor
kwarg (value 0.25, matching the yaml default); all assertions are byte-
identical to before. No test logic was weakened.

## 9. Known limitations

1. The six existing test files needed the mechanical `ema_distance_atr_min=0.25`
   fixture kwarg (see deviation disclosure in §2); assertions unchanged.
2. `trade_id`/`run_id` remain random per run, so raw stdout is not
   byte-identical — all semantic content is.
3. `backtesting.reference_start` accepts any string; malformed ISO raises
   `ValueError` from `datetime.fromisoformat` (loud, fail-closed).
